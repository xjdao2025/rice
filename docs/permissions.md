## 管理身份

当前有五类管理身份，但它们不是一套互斥的角色等级；同一个人可以同时具有多种身份。

| 身份 | 代码依据 | 权限范围 |
|---|---|---|
| 平台运营 | `admin_users.role = operator` | 用户管理、节点资料、内容审核、提案及部分配置；不能增发稻米或管理后台账号 |
| 平台管理员 | `admin_users.role = admin` | 包含运营权限，另可管理后台账号、增发稻米、管理与发放勋章、使用批量模板等 |
| 平台超级管理员 | `admin_users.superuser = true` | 附加标记。关联 C 端身份后，可以管理全平台任务、活动（包括草稿），并以个人稻米发任务 |
| 节点负责人 | `nodes.user_id` | 始终具有本节点管理员权限；只有负责人能任免其他节点管理员。当前节点详情展示此人的个人稻米余额 |
| 节点管理员 | `node_memberships.role = admin` | 管理本节点任务、活动、入会申请及节点钱包；不能任免其他管理员 |

### 平台身份与节点身份的区别

- 后台账号 `Rice.Admin.AdminUser` 与 C 端账号 `Rice.Accounts.User` 独立；后台与 C 端令牌不能互用。
- 后台 `admin` 与节点 `admin` 使用相同名称，但属于不同权限体系，没有自动继承关系。
- `superuser` 不是第三种后台 role。后台敏感接口仍检查 `role = admin`，不会仅因 `superuser = true` 放行。
- `Accounts.put_superuser/1` 按区号和手机号匹配未删除、未停用的后台超级管理员，给当前 C 端用户填充虚拟 `superuser` 字段。
- 超级管理员不自动成为所有节点的管理员。创建节点活动、指定节点发布任务等操作，仍要求实际具有该节点管理员身份。
- 一个节点可以有多个管理员，但 `nodes.user_id` 只指定一个负责人。
- 节点负责人可以将其他正式成员设为管理员或撤销其管理员身份，不能通过该接口撤销自己的负责人身份。

## 普通身份与业务授权

这些身份或标记也参与权限判断，但不应计入上述五类管理身份。

| 身份或授权 | 含义 |
|---|---|
| 未登录访客 | 可访问公开内容，不能执行需要登录或业务授权的操作 |
| 普通 C 端用户 | 有自己的账号与稻米账户，按业务规则参与转账、任务、活动等 |
| 节点正式成员 | `node_memberships.role = member`；属于某个节点，不因此获得管理权限 |
| 个人任务发布授权 | `users.can_publish_tasks = true`；允许没有可管理节点的用户以个人身份发布任务 |
| `node_member` 用户标记 | 控制发起提案和投票的资格；不等于具体节点成员关系，也不等于节点管理员权限 |
| 任务发布者 | `tasks.creator_id`；当前实现中是任务奖励的实际付款人 |
| 任务申请者、承接者 | 根据申请与指派状态，执行申请、交付等操作 |
| 活动创建者、报名者 | 根据活动归属、报名和业务状态执行对应操作 |

任务和活动的可执行操作还受状态约束。拥有管理身份并不意味着任何状态下都能执行所有操作。

## 当前资金权限与账户归属

必须分别识别：**节点负责人、任务发布者、执行管理操作的人**。三者可以不是同一个人。

| 场景 | 当前实际账户或规则 |
|---|---|
| 节点详情余额展示 | 节点负责人个人账户 |
| 任务奖励冻结、退款、结算 | 任务发布者个人账户 |
| 节点收款、发放及节点账本 | 独立节点账户 |
| 活动报名费结算 | 通常结算到申请记录指定的节点账户；没有指定节点时回落到活动创建者账户 |
| 向节点转入稻米 | 登录用户使用自己的余额，不要求是该节点管理员 |
| 从节点发放稻米 | 要求该节点管理员身份 |
| 后台增发稻米 | 要求后台 `role = admin`，并通过发放验证码流程 |

### 已识别、尚未修复的边界问题

1. **管理任务不应自动等于能重新冻结他人的个人资金。** 当前其他节点管理员或超级管理员可以重开已取消、已过期的任务，而冻结账户仍是原发布者；缺少付款人确认。
2. **旧任务需兼容原冻结账户。** `4660fbb` 的节点任务从节点账户冻结，`287297b` 无条件改用发布者账户。旧冻结凭证可能因此无法退款或结算，返回 `grain_reservation_missing`。是否实际受影响取决于升级时是否存在未结清旧任务。
3. **展示与账本口径不统一。** 节点详情展示负责人个人余额，但节点稻米记录读取节点钱包；节点收入不会增加详情展示余额，负责人个人支出却会降低它。
4. **多管理员与负责人更换需要明确规则。** 其他管理员发布任务使用自己的钱，而节点页仍显示负责人的钱；一个负责人管理多个节点时，会重复展示同一账户余额。

建议将业务管理权与资金授权分开；任务在发布时确定并保存实际出资账户，后续退款和结算遵循原冻结凭证。节点公共钱包与负责人个人余额应分别命名和展示。
