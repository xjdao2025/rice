### 补充观察的处理

- 跨区号同手机号不再 `LIMIT 1` 随机选人，歧义时拒绝匹配；仍可使用唯一 handle / 邮箱登录，已有带区号查询不变。
- 管理员 token 的 `last_used_at` 按分钟节流，但权限和停用状态继续每次查询，不引入失效不明的权限缓存。
- 附件元数据明确写入失败时，仅补偿删除本次刚生成的 key；删除失败记录告警，保留原数据库错误。不扫描或删除“未关联”的历史附件。
- 保留必要的旧 daoJwt 兼容，增加 `[:rice, :auth, :legacy]` 计数事件与 `rice.auth.legacy.count` 指标，标签仅 `result`，不携带用户/DID/token。生产历史采集需要现有 reporter 接入，不能把内存事件当成已采集的监控数据。
- 清除了 `attachment_controller.ex` 内部函数一个由调用类型完全覆盖的冗余分支，使原先阻塞的 Dialyzer 告警消失，下载及内容识别语义不变。

## 数据库与发布顺序

本地测试库已执行迁移；生产发布应先后端和 migration，再依赖新接口/行为的前端：

1. 保留此前 `20261022073003_add_feed_and_list_query_indexes.exs`；它使用并发建索引，**同一数据库只运行一个 migrator**，异常时先排查 INVALID 索引，不盲目重跑。
2. `20261022081354_add_post_scan_checkpoints.exs`：补审 checkpoint 表。
3. `20261022082244_add_legacy_session_revocations.exs`：用户旧票关闭标记及只存 SHA-256 的单票撤销名单。
4. `APPVIEW_BASE_URL` 指向支持标准 `searchPosts` 的 AppView；不配置时回退原 labeler URL，仅当同一地址也承载 AppView 才适用。人工审核操作仍使用原 labeler 配置。
5. 后端就绪后发布前端；验证一次登录、改密后 Semi 回访、分页、双会话退出、补审游标推进。不要把迁移回滚当成撤销记录仍然有效：回滚旧票撤销表会丢失相应撤销保护。

### 重要限制与后续运维

- **补审仍是事后治理**，不能阻止用户绕过前端直接写自己的 PDS。首次没有 checkpoint 时从最近一天起步；已有 checkpoint 的窗口不会因停机过期。首次启用前已漏掉的更早历史，如需回补，需要明确回补起点与成本，再单独安排，不擅自全站回扫。
- Web Locks 可用时才提供原点范围跨标签互斥。不支持的环境会保守保留可能正由其他标签轮换的会话，并提示重登，而不是凭一次拒绝误清另一标签。未替代真实多标签浏览器 E2E。
- `deleteSession` 是撤销当前 PDS 会话的请求，不承诺撤销该用户所有设备，也不承诺已签 access JWT 立即失效；这些由上游 PDS 的实际实现和寿命决定。
- 外部 PDS 改密与本地 Postgres **不是分布式原子事务**。正常并发受锁保护；若上游成功后本地提交故障/进程崩溃，仍需按真实上游状态恢复桥接凭据。不要据此宣称消除了所有跨服务故障窗口。
- 旧版已注销但持有资产/职责的历史数据不自动迁移或清零。对账现在保留这些负债；需要业务核对后单独处理。
- 通知缺乏历史申请时不再伪造金额；标题仍按当前名称展示，本轮只保证费用不随重开漂移。
- 附件补偿覆盖明确返回的元数据插入失败，不能保证覆盖进程崩溃、外层事务随后回滚或存储不可用；相关告警需要运维接入，不存在“自动清理所有历史孤儿”的保证。
- R14 的详情分页、节点父目录分页以及完整承接者协议没有擅自破坏。状态投影跨 SQL/前后端的结构性统一、仅测试使用的旧通知读取入口，仍作为架构整理事项，不为减行数改写稳定接口。
- 旧 DAO 兼容仍按原计划在 **2026-12-31** 退出；应在用量确认和迁移通知后同步删除兼容模块、单票名单、用户标记及相关测试，不能只删校验逻辑或提前回滚撤销表。
